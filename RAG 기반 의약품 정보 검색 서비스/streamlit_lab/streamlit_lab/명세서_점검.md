# 프로젝트 명세서 대조 점검

점검일: 2026-10-23. 원본 `AI코어프로젝트_2회차_요구사항정의서.pdf` 23쪽을 다시 추출하여 현재 코드와 대조했습니다. 상시 자동 감시를 하는 것은 아니며 이번 요청에 따라 재검토했습니다.

결론: 사용 가능한 프로토타입이지만 제출 요구사항 전체 완료로 표시할 단계는 아닙니다. 기존 테스트 통과와 명세서 전체 충족은 구분합니다.

## 실행 방법

서버가 살아 있으면 http://localhost:8502 를 다시 엽니다. 완전히 종료했다면 `C:/SSAFY/workspace/project/05. AI Core2 프로젝트/교육생배포용/streamlit_lab/실행.cmd`를 실행합니다. 터미널은 켜 둡니다. 포트 8502가 이미 사용 중이라고 나오면 기존 서버 주소를 열고 실행 파일을 중복 실행하지 않습니다.

### 필수 문서의 표 제외 문제

명세서 13쪽은 선택 항목 자체 문서가 선별·길이 등의 제외 규칙보다 우선하여 항상 색인되어야 한다고 명시합니다. 현재 표 포함 청크 75개를 제외하고, 검색된 절이 16,000자를 넘으면 답변 입력에서 보류합니다. 원본을 보관했다는 사실만으로 항상 색인 요건을 충족했다고 볼 수 없습니다.

해결은 표를 무조건 평문으로 사용하도록 차단을 해제하는 방식이 아닙니다. 문서 등록·보존과 답변 사용 가능 상태를 분리하고, 표의 구조 및 조건을 검증한 표현을 색인하며, 검증 전 문서는 보류 상태를 명시해야 합니다. 이 처리와 수업 요구의 평가 방식을 함께 정리할 필요가 있습니다.

- 기능별 요구사항 정의서와 현재 판정 대조표의 제출본 정리.

- 청크 크기·중복·Top-k를 바꿨을 때의 차이와 설정 선택 이유.
- 명세서 4장의 항목별 실행 화면과 실제 실패/예외 상황 증빙.
- 학교 제공 셀프 체크리스트 및 동료 상호 점검 결과. AI가 동료 점검을 대신 완료했다고 기록하면 안 됨.
- 선택 심화 기능의 실제 자료·실행 결과·비교 문서.
- 최종 README, 코드·수집/색인 스크립트, 비밀정보 제외 점검, 지정 제출 ZIP명.

## 권장 진행 순서

1. F2004/F2005의 필수 문서·표 처리와 선별 전후 로그를 정리합니다.
2. 초기 데이터/키/색인 오류 화면을 점검하고 대표 질문과 조건 탐색의 평가 세트를 늘립니다.
3. 허용된 추가 근거를 소량 등록하여 F2016의 실제 복수 출처 인용을 검증하거나, 다른 심화 과제를 선택합니다.
4. 설계문서·실행 화면·체크리스트·제출 ZIP을 마무리합니다.

이번 검증은 회귀 검사 24건, 실제 기본 질문→제품별 용량 확인 분기, 벡터 검색·Top-k, 고정 프롬프트 사례 7건입니다. 표·기관 지침·모든 임상 주장까지 검증 완료한 것으로 표시하지 않습니다.
