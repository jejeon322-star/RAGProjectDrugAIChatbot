본 폴더는 의약품 제품을 식별하고 공식 근거 문서를 검색하기 위한 원본 및 가공 데이터를 보관한다. 제품 기본정보와 상세 근거 문서를 분리하며, 제품 식별자 `drug_id`로 연결한다.

## 3. 폴더 구조

프로젝트 루트에 수집·변환 스크립트를 두고 실행한다. 아래 구조는 변환까지 실행했을 때의 결과다.

```text
data/
├─ README.md
├─ raw/
│  ├─ list/
│  │  └─ page_0001.json
│  ├─ detail/
│  │  └─ 200410896.json
│  └─ collection_log.json
└─ prepared/
   ├─ drugs.json
   ├─ documents/
   │  ├─ 200410896_EE.json
   │  ├─ 200410896_UD.json
   │  ├─ 200410896_NB.json
   │  └─ ...
   └─ quality_report.json
```

- `raw/list/`: 목록 API의 페이지별 응답. 재수집 시 같은 페이지 파일은 갱신될 수 있다.
- `raw/detail/`: 제품별 상세 API 원본. 파일명은 `ITEM_SEQ`를 사용한다.
- `raw/collection_log.json`: 자동 수집이 기록한 제품별 수집 시각. 기록이 없는 제품도 있을 수 있다.
- `prepared/drugs.json`: 제품 목록과 제품별 검색 텍스트.
- `prepared/documents/`: API 공식 본문을 항목별로 정리한 근거 문서.
- `prepared/quality_report.json`: 변환 오류, 본문 미확보 및 표 처리 건수.

## 4. 제품 기본정보

항목 1건은 원본 품목 식별번호 `ITEM_SEQ`로 구분되는 제품 1개다. `drug_id`는 `mfds:{ITEM_SEQ}`로 만든다. 같은 성분이라는 이유만으로 다른 제품을 합치지 않는다.

| 저장 필드 | 원본 또는 생성 기준 |
| --- | --- |
| `drug_id`, `source_record_id` | `ITEM_SEQ` |
| `product_name`, `product_name_en` | `ITEM_NAME`, `ITEM_ENG_NAME` |
| `company_name` | `ENTP_NAME`; 실제 제조소와 동일하다고 가정하지 않음 |
| `contract_manufacturer_raw` | `CNSGN_MANUF` |
| `prescription_type` | `ETC_OTC_CODE` |
| `material_name_raw` | `MATERIAL_NAME`; 성분·함량·단위·기준량 원문 |
| `main_ingredient_raw`, `main_ingredient_en` | `MAIN_ITEM_INGR`, `MAIN_INGR_ENG` |
| `appearance_raw` | `CHART` |
| `storage_method`, `valid_term` | `STORAGE_METHOD`, `VALID_TERM` |
| `atc_code`, `permit_status` | `ATC_CODE`, `CANCEL_NAME` |
| `source_record_change_date_raw` | `CHANGE_DATE`; 레코드 변경일 원문 |
| `document_ids` | 연결된 근거 문서 ID 목록 |
| `search_text` | 확보된 기본정보를 규칙으로 조합한 제품별 검색 텍스트 |

현재 변환기는 함량·제형·투여 경로를 별도 구조화 값으로 확정하지 않는다. `ingredients`, `strength_text`, `dosage_form`, `routes`, `aliases`의 빈 값은 추후 검증·보완 대상이며, 성분이나 경로가 없다는 의미가 아니다. 원본 제품명과 성분 문자열은 보존한다.

## 5. 상세 근거 문서

| 원본 필드 | 문서 구분 | 원문 링크 필드 |
| --- | --- | --- |
| `EE_DOC_DATA` | 효능·효과 | `EE_DOC_ID` |
| `UD_DOC_DATA` | 용법·용량 | `UD_DOC_ID` |
| `NB_DOC_DATA` | 사용상의 주의사항 | `NB_DOC_ID` |
| `PN_DOC_DATA` | 전문가용 추가 정보 | 해당 링크가 없으면 `source_url`은 비워 둠 |

각 문서는 `doc_id`, `drug_id`, 제목, 본문, 출처, 원본 필드, 수집 시각 및 `content_hash`를 가진다. XML의 ARTICLE 제목과 PARAGRAPH 순서를 저장하고 원본 XML도 보존한다. 빈 ARTICLE 제목만 존재하는 경우에도 원문 구조를 유지한다.

표는 검색용 텍스트와 `raw_content`를 함께 보관한다. 검색용 텍스트만으로 병합 셀·행·열 관계를 정확히 재현했다고 가정하지 않는다. 표의 수치·조건을 답변에 사용하려면 원문 표와의 대조 또는 추가 구조화 검증이 필요하다.

`CHANGE_DATE`는 모든 문서의 개정일로 간주하지 않는다. 확인되지 않는 개별 문서 개정일은 `source_updated_at: null`로 유지한다. 수집 시각은 원문 개정일과 별개다.

문서 파일은 공식 자료의 정리본이며, LLM으로 내용을 새로 생성하지 않는다. 검색용으로 만든 요약이나 이전 챗봇 답변을 원문 근거로 대체하지 않는다.

## 6. 수집·변환 실행

프로젝트 루트의 `.env`에 발급받은 Decoding 인증키를 설정한다.

```dotenv
MFDS_API_KEY=본인의_Decoding_인증키
```

```bash
# 최초 실행 전 필요한 경우 설치
python -m pip install requests python-dotenv

# 기본 3개 수집, 이후 100개로 확장
python collect_drugs.py
python collect_drugs.py --limit 100

# 저장된 원본 전체 변환
python prepare_drugs.py
```

`--limit 100`은 이번 실행에서 목록 순으로 확보하려는 고유 제품 수다. 기존 정상 상세 파일은 재사용하며, 다른 경로로 이미 저장한 파일이 있으면 폴더 전체 제품 수는 100개보다 많을 수 있다. 수집기는 기존 정상 파일의 최신성을 자동 확인하지 않는다.

변환은 API·LLM·임베딩을 호출하지 않는다. 변환 후 `quality_report.json`을 확인하고, 제품 하나 이상을 골라 제목·단위·적용 조건·표·출처가 보존되었는지 원본과 비교한다. 동일 출력 폴더에 재변환할 때 입력에서 제거된 제품의 예전 문서가 남을 수 있으므로, 최종 색인 전 `drugs.json`의 `document_ids`와 대조한다.

## 7. RAG 활용 계획과 현재 범위

- `drug_meta`: 제품별 `search_text`를 저장하여 제품 식별 보조와 조건 탐색에 사용한다.
- `drug_docs`: 원문을 주제·조건을 보존하며 청킹하고 임베딩하여 상세 근거 검색에 사용한다.
- 청크에는 제품 ID, 문서 ID, 원문 위치, 버전 정보를 연결한다. 제품명이나 성분명이 비슷하다는 이유로 다른 제품의 조건을 섞지 않는다.
- 사용자 대화와 현재 대상은 별도 세션에서 관리하고 의약품 근거 데이터에 포함하지 않는다.

현재 파일 준비는 원본 수집 및 변환 단계다. 벡터 DB 색인, 질문 기반 검색어 추출, 후보 문서 선별, LangGraph 검색·생성, 최종 답변 검증이 완료되었다는 의미는 아니다.

## 8. 적용 범위와 한계

- 본문이 있다는 이유만으로 AST, 주사제 배합적합성, 희석·투여 속도, 기관별 대응 지침을 모두 확보했다고 판단하지 않는다.
- 자료 미확보와 문서 내 미기재를 구분하며, 이를 ‘금기 없음’, ‘병용 가능’, ‘AST 불필요’로 바꾸지 않는다.
- 원문에 다른 제형·함량의 설명이나 비교시험이 포함될 수 있다. 해당 조건을 보존하고 선택한 제품에 적용되는지 확인한다.
- 수집 당시 자료는 최신 허가사항과 다를 수 있다. 공식 원문을 확인할 수 있는 링크와 수집 이력을 표시한다.
